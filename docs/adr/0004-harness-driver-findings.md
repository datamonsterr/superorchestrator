# Harness driver findings from the M3 spikes

Status: accepted. Recorded 2026-10-22 on a real machine with codex-cli 0.163.0, Claude Code 2.1.308, opencode 1.18.35, agy 1.4.4 and bwrap. Fixtures are in `crates/so-harness/tests/fixtures/<harness>/` (scrubbed: home path is `/home/user`, scratch paths are `/work/spike-*`, installation and account ids are placeholders). Every claim below was observed unless marked "unverified".

Test prompt: `Create a file hello.txt containing the word hi, then reply with exactly: done`, in a throwaway `git init` directory.

## Spec deviations (read first)

1. **agy `-p` takes the next token as its prompt.** The SPEC argv `agy ... -p --input-format ...` exits 2 ("-p took "--input-format" as its prompt"). Use `-p=` (empty prompt) when feeding stream-json on stdin.
2. **agy stream-json input is not the Claude shape.** One NDJSON object per line: `{"event":"user","message":{"content":"<text>"}}`. Anything else is rejected or ignored with a warning.
3. **agy `--gemini_dir` is not in `agy --help`** but works. Do not bind the profile over `~/.gemini` when the profile's `config` is a symlink to `~/.gemini/config` (the agent-farm profiles are): agy fails with `mkdir ~/.gemini/config: file exists`. Pass `--gemini_dir=<profile>/.gemini` directly. The bwrap wrapper is still harmless (`--bind / /`), but the extra `--bind <dir> ~/.gemini` from ADR 0003 must only be used for real directories.
4. **agy has no `--mcp-config`, and project-scope config is not read.** Per-run MCP needs a per-run gemini dir (see agy section).
5. **opencode does have structured output.** `prompt_async` and `POST /session/{id}/message` accept `format: {"type":"json_schema","schema":{...},"retryCount":N}`. SPEC section 4 says opencode has no schema option. Prefer the native option and keep the validate-and-reprompt loop as a fallback. (Not exercised against a model; shape taken from the served OpenAPI.)
6. **codex `thread/start` has no reasoning-effort parameter.** Effort is `effort` on `turn/start`, or `config: {"model_reasoning_effort": "..."}` on `thread/start` (verified: the response echoes `reasoningEffort: "low"`). SPEC wording `model_reasoning_effort` is correct only as a config key.
7. **`claude --append-system-prompt-file` and `--max-turns` work but are absent from `claude --help`.** Both are accepted (system file verified in effect; `--max-turns` accepted, limit not triggered). Answer to the SPEC spike: `--max-turns` exists in 2.1.308. `--verbose` is needed alongside `--output-format stream-json` in `-p` mode (always passed in our runs).
8. **opencode `--port 0` prefers 4096.** The first server bound 4096; the second got a random port. Always parse the printed `opencode server listening on http://127.0.0.1:<port>` line, never assume the port.
9. **opencode needs a directory per request.** Send header `x-opencode-directory: <cwd>` on every call (session, prompt, abort, status). The server is not tied to one cwd.
10. **codex model names**: there is no `-mini` model on this machine; `model/list` returns `gpt-6.1-sol`, `gpt-6-astra`, `gpt-6-sol`, `gpt-6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` (efforts low..max, `ultra` on most). Do not hardcode names; read `model/list`.

## codex

Transports (`codex app-server --help`): `--listen stdio://` (default), `unix://[PATH]`, `ws://IP:PORT`, `off`. WebSocket auth: `--ws-auth capability-token|signed-bearer-token`, with `--ws-token-file <abs path>`, `--ws-token-sha256 <hex>`, `--ws-shared-secret-file`, `--ws-issuer`, `--ws-audience`, `--ws-max-clock-skew-seconds`. Verified: with `--ws-auth capability-token --ws-token-file F` a client without `Authorization: Bearer <token>` gets HTTP 401 on upgrade, with it `initialize` works. The ws server also serves `GET /readyz` and `GET /healthz` (200) and binds localhost only.

Launch: `CODEX_HOME=<home> codex app-server --listen ws://127.0.0.1:<port> --ws-auth capability-token --ws-token-file <run>/ws-token`. Stdio is simpler for a supervisor-owned child and was used for the recorded transcript (`codex/transcript-stdio.jsonl`); the same JSON-RPC (no `jsonrpc` field) flows on both.

Handshake: request `initialize {clientInfo:{name,title,version}, capabilities?}` then notification `initialized`. Response `{userAgent, codexHome, platformFamily, platformOs}`.

## claude

Flags confirmed in `claude --help`: `-p/--print`, `--input-format stream-json`, `--output-format stream-json`, `--verbose`, `--dangerously-skip-permissions`, `--session-id <uuid>`, `--mcp-config`, `--strict-mcp-config`, `--json-schema`, `--model`, `--effort low|medium|high|xhigh|max`, `--resume [id]`, `--replay-user-messages`, `--include-partial-messages`, `--no-session-persistence`, `--max-budget-usd`. Accepted but unlisted: `--append-system-prompt-file`, `--max-turns` (deviation 7).

Launch argv used: `claude -p --input-format stream-json --output-format stream-json --verbose --dangerously-skip-permissions --session-id <uuid> --mcp-config <run>/mcp.json --append-system-prompt-file <run>/system.md --max-turns 8 --model haiku --effort low` with `CLAUDE_CONFIG_DIR` unset (default account) in the spike.

Live message: write `{"type":"user","message":{"role":"user","content":[{"type":"text","text":"..."}]}}` + newline to stdin. The process stays alive after each `result` and waits for the next stdin line (verified with two messages; the second turn emits a fresh `system init` with the same `session_id`, and the appended system prompt still applied). Closing stdin ends the process with exit 0. A message sent mid-turn is queued (control response lists `still_queued`).

Cancel: write `{"type":"control_request","request_id":"<id>","request":{"subtype":"interrupt"}}`. Verified: reply `control_response {subtype:"success", response:{still_queued:[]}}`, a user message `[Request interrupted by user]`, then a `result` with `stop_reason:"tool_use"` for the interrupted turn; the process stays alive for more input. Hard cancel is SIGTERM.

Events (`claude/transcript.jsonl`, `claude/interrupt.jsonl`): `system` subtypes `hook_started`, `hook_response` (user hooks; ignore), `init {cwd, session_id, tools, ...}`, `task_summary {detail}`, `post_turn_summary`, `thinking_tokens`; `assistant {message:{content:[{type:"text"|"tool_use",...}],usage}, session_id}` (tool call = `tool_use {id,name,input}`); `user {message:{content:[{type:"tool_result",tool_use_id,content,is_error}]}}`; `rate_limit_event {rate_limit_info:{status,resetsAt,rateLimitType,unifiedWindows:{five_hour:{utilization,resetsAt},seven_day:{...}}}}` (utilization is a 0-1 fraction; this is a free usage source for claude, contradicting "ledger only" in SPEC 6.1, so use it as source `event`); final `result {subtype:"success", result, session_id, total_cost_usd, usage:{input_tokens,output_tokens,cache_read_input_tokens,cache_creation_input_tokens}, modelUsage, stop_reason, terminal_reason, permission_denials}` (key order is not stable; match on `"type":"result"`; also has `is_error`, `num_turns`, `api_error_status`).

Native session id: the `--session-id` uuid, echoed as `session_id` in every event. Resume: `claude -p --resume <uuid> ...` verified (the codename set by the appended prompt was remembered); interactive join `claude --resume <uuid>` from the same cwd and `CLAUDE_CONFIG_DIR`. Structured output: `--json-schema <string>` exists (not exercised). Join while running: not supported by the process (stdin owned by supervisor); the SPEC rule "after the run pauses or ends" holds.

Errors: bogus model exits 1 with text `There's an issue with the selected model (bogus-xyz). It may not exist or you may not have access to it.` and marker `[claude-code:unrecognized_model]` (`claude/errors.txt`). No quota error captured; rely on `rate_limit_event.rate_limit_info.status != "allowed"` and `result.is_error`/`subtype` plus text patterns ("usage limit", "rate limit", "Invalid API key", "Please run /login") marked unverified.

## opencode

Launch: `OPENCODE_SERVER_PASSWORD=<pw> [OPENCODE_CONFIG=<run>/opencode.json] opencode serve --hostname 127.0.0.1 --port 0`; stdout line `opencode server listening on http://127.0.0.1:<port>`. Auth: HTTP Basic, username `opencode` (override `OPENCODE_SERVER_USERNAME`), password `OPENCODE_SERVER_PASSWORD`; no header returns 401. `GET /global/health` -> `{"healthy":true,"version":"1.18.35"}`. OpenAPI 3.1 at `GET /doc` (JSON). Subset: `opencode/openapi-subset.json`.

Endpoints (all verified unless noted; send `x-opencode-directory: <cwd>`):
- `POST /session {title?, parentID?, model?:{id,providerID,variant?}, permission?}` -> session object, id `ses_...` (fixture `opencode/session-create.response.json`).
- `POST /session/{id}/prompt_async` body `{model:{providerID,modelID}, variant?, agent?, system?, tools?:{name:bool}, format?, noReply?, messageID?, parts:[{type:"text",text}]}` -> 204. Provider and model are separate fields (`providerID:"opencode"`, `modelID:"glm-5.3-flash-free"`); `variant` is the provider-specific reasoning effort. A second `prompt_async` on a busy session queues a message (not exercised).
- `POST /session/{id}/abort` -> `true`; the running assistant message gets `error:{name:"MessageAbortedError"}` and the session goes idle (`opencode/abort.sse`).
- `GET /session/status` -> `{<sessionId>:{type:"busy"}}` or `{}` when idle. `GET /session/{id}/message` lists messages and parts. Also seen in the spec: `/permission`, `/question` and their reply routes.
- `GET /event` SSE: lines `data: {"id":"evt_...","type":"...","properties":{...}}`, blank line between. Types seen: `server.connected`, `server.heartbeat` (about every 30 s), `session.created`, `session.updated`, `session.status {sessionID,status:{type:busy|idle}}`, `session.idle`, `session.diff`, `session.error {sessionID,error:{name,data}}`, `message.updated {info}` (assistant `info` has `tokens:{input,output,reasoning,cache:{read,write}}`, `cost`, `modelID`, `providerID`, `time.completed`), `message.part.updated {part}` (part types `step-start`, `tool` with `tool` and `state`, `text`, `step-finish`, `patch`), `message.part.delta`, `file.edited`, `file.watcher.updated`. Startup noise (`plugin.added`, `catalog.updated`, ...) is filtered from fixtures. Completion = `session.idle` (or `session.status` idle). The event stream is server-wide, filter by `sessionID`. Fixture: `opencode/task.sse` (real tool call then final text `done`).

Per-run MCP and agent config (SPEC spike): **`OPENCODE_CONFIG=<file>` works.** It is merged over the global config: a run file with `mcp.so` (local command, `environment`), `agent.so-child` and `permission:{"*":"allow"}` showed up in `GET /mcp`, `GET /agent` and `GET /config` while global MCP servers stayed. Template: `opencode/run-config.example.json`. Project `opencode.json` was not needed. Because the global config is merged in, per-run isolation is additive, not exclusive. Full permissions: `permission:{"*":"allow"}` in that file; `opencode run --auto` is the CLI equivalent.

Native session id: `ses_...`. Join: `opencode attach <url> --session <id>` (flags in `opencode/help.txt`; password via `-p`/`OPENCODE_SERVER_PASSWORD`); after the run `opencode --session <id>` (`-s`, `--continue`, `--fork` exist). Resume = just prompt the same session id on a fresh server with the same data dir. `opencode run` is not needed.

Models: `opencode models` (`opencode/models.txt`) lists `provider/model`. Free ones end in `-free` (`opencode/glm-5.3-flash-free`, `opencode/deepseek-v4.1-flash-free`, ...). In this session `glm-5.3-flash-free` completed correctly but took about 75 s; `deepseek-v4.1-flash-free` produced no output for 90 s and had to be aborted, so free models can stall; give them a stall timeout. Usage fields come from `message.updated` tokens and cost (ledger/event source only; no quota endpoint).

Errors: `opencode-go/claude-haiku-5-5` -> `session.error` name `APIError`, `statusCode:402`, message `Upstream request failed: Insufficient account funds`, `isRetryable:false` (`opencode/error-402.sse`): classify as quota. Bogus model: `opencode run` exits 1 with `UnknownError "Unexpected server error. Check server logs for details."` (no useful text; `opencode/errors.txt`); a model id that is merely unlisted gives `UnknownError "Model not found: <id>. Did you mean: ..."` (`opencode/error-model-not-found.sse`), classified `config`. Treat `APIError` with status 402/429 as quota/rate_limit, 401/403 as auth.

## agy

Flags (`agy --help`, `agy/help.txt`): `--print/-p <prompt>`, `--input-format text|stream-json` (stream-json requires `--output-format stream-json`), `--output-format text|json|stream-json`, `--dangerously-skip-permissions`, `--model`, `--effort low|medium|high|xhigh|max`, `--json-schema <string|path>` (for stream-json only the final result), `--conversation <id>`, `--continue`, `--agent`, `--mode accept-edits|auto|plan`, `--add-dir`, `--log-file`, `--print-timeout`, `--sandbox`. `--gemini_dir` is accepted but unlisted (deviation 3). `agy models` prints `id<TAB>name` lines (`agy/models.txt`); the model id already carries effort for Gemini (`gemini-3.8-flash-low|medium|high`), so `--effort` may be redundant there (it was accepted together with `gemini-3.8-flash-low`).

Effort values (agy 1.4.5): `--effort` accepts only `low|medium|high|xhigh|max`, and `--effort thinking` is refused at launch. Thinking models are separate model ids (`claude-sonnet-4-6  Claude Sonnet 4.6 (Thinking)`, `claude-opus-4-6-thinking`). Decision: `effort = "thinking"` stays in choices as a router-level hint (heuristic rank 3, equivalent to before). The agy driver maps it to no `--effort` flag. Other harness values: claude `--effort` takes `low|medium|high|xhigh|max` (`claude --help`); codex `model_reasoning_effort` takes the per-model `supportedReasoningEfforts` from `model/list`, validated here against `minimal|low|medium|high|xhigh|max|ultra`; opencode `--variant` is provider-specific and not validated. `so_core::Harness::effort_problem` holds the table; drivers refuse an invalid effort before spawning, the router skips such choices and `doctor` reports them.

Launch argv that worked: `bwrap --die-with-parent --new-session --bind / / --dev-bind /dev /dev -- agy --gemini_dir=<profile>/.gemini -p= --input-format stream-json --output-format stream-json --dangerously-skip-permissions --model gemini-3.8-flash-low --effort low`, stdin kept open.

Live message: stdin `{"event":"user","message":{"content":"..."}}`. Verified two turns on one process; it stays alive between turns and exits 0 on stdin EOF. Output (`agy/transcript.jsonl`): `{"event":"init","conversation_id":"<uuid>","init":{model,cwd,tools,permission_mode}}`, then `{"event":"step_update","step_update":{conversation_id,step_index,state:ACTIVE|DONE,step_type:user_input|agent_response|tool|unknown,tool_name?,tool_info?:{name,parameters},text_delta?,duration_seconds?,usage?}}`, then `{"event":"result","result":{conversation_id,status:SUCCESS|ERROR,response,error?,duration_seconds,num_turns,usage:{input_tokens,output_tokens,thinking_tokens,cache_read_tokens,total_tokens}}}`. **Conversation id field: `conversation_id`, top level of `init` and inside `step_update` and `result`.** Tool calls: `step_type:"tool"` with `tool_name` (`write_file`, `run_command`, ...), ACTIVE then DONE. `result.usage` is cumulative over the conversation.

Cancel: SIGINT to agy ends the turn with `result.status:"ERROR"` and exits 1 (verified on a `sleep 50` command). Conversation stays resumable. SIGTERM was not tried.

Resume: `agy --gemini_dir=<profile> --conversation <id> -p "<prompt>"` verified (it remembered `hello.txt`). Join after the run: `agy --conversation <id>` (interactive, not exercised).

Per-run MCP (SPEC spike): **config lives at `<gemini_dir>/config/mcp_config.json`**, format `{"mcpServers":{"<name>":{"command","args","env","disabled"}}}`, written by `agy mcp add [-e K=V] <name> <cmd> [args]` and read by `agy mcp list` (verified in a scratch gemini dir under bwrap). Project-scope files in the cwd (`.agents/`, `.gemini/`, `.agy/`, `.antigravity/`, `mcp_config.json`, `.mcp.json`) were not picked up (`mcp list` empty; agent did not see the server). The MCP child inherits agy's environment plus the `env` map: `SUPERORCHESTRATOR_RUN_ID` set on the agy process was visible to the MCP server, so one static server entry plus run env is enough. Problem: agent-farm profiles symlink `config` to `~/.gemini/config`, so `agy mcp add` on a profile edits the shared config. Recommended driver approach (verified signed in, result SUCCESS): build `<run>/gemini` with symlinks to the account's `antigravity-cli`, `plugins`, `projects`, `skills`, a real `config` directory copied from the account, and a run-specific `mcp_config.json`; pass `--gemini_dir=<run>/gemini`. Note a server that never completes the MCP handshake can make the turn hang (seen with a dummy command; the process then needed `timeout`).

Usage: `agy --gemini_dir=<home> --print /usage` prints four TSV lines (`agy/usage-ok.txt`, `agy/usage-exhausted.txt`): `<pool>\t<window label>\t<remaining pct or disabled>\t<ISO8601 reset>`. Pools: `Gemini Models`, `Claude and GPT models`. Labels: `Weekly Limit Remaining`, `Five Hour Limit Remaining`. Percentage is remaining (not used); the value can be `disabled` for a window; five-hour reset is rolling (`resetsAt` is the next reset time). Parse by splitting on tabs. A not-signed-in or ineligible profile prints `error: Eligibility check failed: Your current account is not eligible for Antigravity...` plus a sign-in URL (do not store it).

Errors (`agy/errors.txt`): exhausted quota -> stderr `error: Individual quota reached. Please upgrade your subscription to increase your limits. Resets in 40h19m40s.` and `AGY_ERROR: {"short_error":"RESOURCE_EXHAUSTED (code 429): ...","status":"RESOURCE_EXHAUSTED","error_code":429,"retryable":true}`, and in stream-json a `result` with `status:"ERROR"` and the same text in `error`. Classify: `RESOURCE_EXHAUSTED`/`quota reached` = quota. Bogus model: exit 1, `invalid model selection (--model "bogus-model" ...) is not recognized`, with the available model list. The `~/.gemini` and `agy_worker_1` accounts were out of Gemini quota during the spike; `agy_worker_5` was used for the recorded run.
