# Real-machine smoke test, 2026-10-23

This is the SPEC 21 smoke test, run by hand on Arch Linux (x86_64) with `scripts/smoke.sh`. It used real harnesses and a release build from `feat/v1` at 5ffa73e (version 0.1.0). It ran in an isolated config dir, socket and wrapper dir. It never read or wrote the real config, wrappers or installed skill.

Harness versions: codex-cli 0.163.0, agy 1.4.5, opencode 1.18.35, Claude Code 2.1.308.

## Run 1: all harnesses

Accounts: codex `~/.codex-acc1` and `~/.codex-acc2`, opencode default home, claude `~/.claude`, agy `agy_worker_3`.

| Step | Result | Note |
|---|---|---|
| init and imports (6 accounts) | PASS | |
| delegate codex | PASS | `claude -p` delegated through `superorchestrator mcp`; the run succeeded |
| delegate opencode | FAIL (account) | The harness reported `APIError 402: Upstream request failed: Insufficient account funds`. The run was classified `quota` and the account was put on cooldown. |
| delegate claude | PASS | |
| delegate agy | FAIL (account) | agy reported `Individual quota reached ... Resets in 30h32m48s`. The run was classified `quota` and the gemini pool was put on cooldown. |
| join codex | PASS | A live codex run printed its `join` command (`codex resume --remote ws://127.0.0.1:<port> --remote-auth-token-env SO_WS_TOKEN <thread>`) |
| failover codex | PASS | After the first codex account was flagged, the run went to the second |
| route eval | SKIP | `OPENROUTER_API_KEY` was not set |

Both failures were limits on the accounts used, not product defects. The product classified each one correctly and flagged the account.
